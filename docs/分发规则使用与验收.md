# 分发规则使用与验收

## 操作入口

1. 管理员进入「系统设置 → 分发规则」，可以修改累计售卖上限、去重天数、KA上限、同媒体重复售卖开关、全局分发开关和自动分发开关。修改前后值实时显示，必须填写原因。最近操作审计的「查看变更」可查看旧值、新值、版本和操作者。
2. 进入「需求池 → 详情」，设置项目（KA/会员）及是否自动接收。新需求默认不自动接收，自动接收必须明确项目。
3. 手动分发仍通过「匹配分发 → 生成匹配预览」。预览选择项目后即时重检KA规则，确认时再次检查并占用额度。
4. 自动分发默认关闭。开启系统开关和需求自动接收后，服务每30秒扫描。仅唯一候选，或已人工指定目标需求的线索自动创建并执行本地模拟任务。
5. 多个候选需求显示在「匹配分发 → 自动分发 → 待人工分配」。选择目标后点击「指定并分发」。也可选中多条线索和唯一一项需求，点击「将所选线索绑定到所选需求」。
6. 在「分发记录」查看手动/自动方式、规则版本及模拟回调链路。已有项目UNKNOWN的历史记录可用「补录项目」登记。

## 规则口径

- 初始累计上限2次、KA上限1次、去重窗口30天、禁止同一最终媒体重复售卖。KA+KA禁止，KA+会员及不同最终媒体的会员+会员允许。
- 同一条线索的全部历史累计计次，不随30天结束而清零。同手机号、同品牌的其他线索在滚动窗口内共享限制，车型和来源渠道变化不绕过规则。窗口按售卖/预占时间检查，并立即使用最新天数。
- 精确同车型的入库重复合并及Excel/CSV预检也使用可配置窗口。同品牌不同车型保留各自意向记录，分发时统一检查窗口内售卖记录。
- 历史手工/表格售卖记录计次。待发送预占、结果未知、已接收/入库均占用；明确未接收的失败及未发送取消释放。入库后无效回调不自动释放售卖额度。
- 历史项目不明确时，先补录项目再进行新的KA分发，避免遗漏历史KA。
- 系统调低上限或暂停分发时重检并取消不符合要求的未发送任务。已发送历史和原规则快照保留。
- 自动扫描只执行AUTO模式任务，不代为发送手动创建的待发送任务。
- 多需求之间不按星级、价格、优先级或到期时间自动抢占，多个候选交人工选择。

## 星级

有效达成率=已确认有效数量/目标数量，最大显示100%。在途占用需求配额，不计有效。按原始比率划分：[0,20%)五星、[20,40%)四星、[40,60%)三星、[60,80%)二星、[80,100%)一星，达到100%显示「已达成」，不再新增分发。星级只用于展示完成缺口，不表示剩余时间，也不参与排序。

## 接口

- GET/PATCH `/api/v1/settings/distribution`：读取/修改规则。PATCH需要当前version及reason。配置操作需distribution_rules权限，当前管理员拥有此权限。
- POST `/api/v1/matches/preview`：可传projects（需求ID→KA/MEMBER），选项目后重新预检。
- POST `/api/v1/dispatches`：pairs、projects、preview_version及Idempotency-Key。手动、自动使用同一dispatch事务及同一规则校验。
- PATCH `/api/v1/demands/{id}`：增加auto_enabled（0/1）、sale_project（KA/MEMBER/UNKNOWN）。开启自动接收时禁止UNKNOWN。
- GET `/api/v1/distribution/auto`：最近100条自动处理结果及候选/原因。
- POST `/api/v1/distribution/auto/run`：立即扫描。系统开关关闭时返回paused=true。
- POST `/api/v1/distribution/auto/bind`：pairs指定每条线索唯一目标需求。需求需开启自动接收及设置项目，绑定不会绕过分发限制。

数据库迁移015增加规则参数、需求自动接收设置、交付方式及规则快照、自动分配记录和绑定记录，保留原业务数据。API旧字段max_media_count保留兼容名称，现在表示累计售卖上限，不再以不同媒体集合数量计次。

## 2026-11-23：主体项目独立启停（本地待发布）

- 线索供应每行“停用项目/启用项目”只改变该主体的会员或KA项目；另一项目及主体总开关不变。主体总开关移至“编辑主体”，明确影响全部项目。
- 主体总开关与项目开关必须同时启用才参与新匹配。手动、自动、预览、创建及当前可匹配库存共用此规则；关闭项目后，旧页面提交也会被后端拒绝。
- 停用取消该项目尚未首次发送的排队交付并释放预占；已发送交付、历史快照及回调处理保留。重新启用恢复原需求展示，不自动复活已取消交付。
- 项目停用后，需求池当前列表、筛选选项、汇总和匹配采购选项隐藏该项目需求；不删除原始数据，也不改写逐条需求状态。来源管理仍可查看配置及停用提示。
- PATCH /api/v1/partner-projects/status要求settings权限、partner_id、project、enabled（0/1）及version。按组织限制，过期版本返回冲突；目录返回独立enabled。
- 028迁移新增partner_projects.enabled，已有项目默认1，保留主体原enabled值。旧系统连带关闭的主体无法可靠推断用户意图，不自动恢复：需要明确启用主体总开关，再停用不需要的项目。


## 2026-11-23：API KA的提交量口径（仅本地）

API KA每日量级限制当天首次提交笔数，不按最终有效量回补。可用量为当天上限减已首次发送交付减未发送预占，截断为0；取消未发送任务释放预占，已发送失败或无效仍占提交次数。手动、自动、预览、创建及worker都复用同一校验。每日额度日期过期时阻止新分发，08:00自动拉取或人工重新拉取后恢复当日额度。月度总量仅展示，不限制整个项目总分发。

此规则只适用于api_submit_limit非空需求，既有QQ/Excel每日需求保持原规则。KA需求读取接口不等于会员提交接口，禁止通过zhemanhui-v1会员适配器发送这类KA需求。
