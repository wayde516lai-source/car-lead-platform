# 易车线索池与需求池字段

适用于本地测试版，依据用户提供的《会员线索对接文档0704.pdf》中的线索保存、城市列表、车款列表和回调关联规范。线索推送默认处于模拟模式。

| 位置 | 字段 | 填写规则 |
|---|---|---|
| 易车需求 | platFormId、plat | 易车分配的平台 ID、客户端平台，提交前必填 |
| 易车需求 | clueTypeId | 默认1询价；支持2贷款、83。83必须同时提供 crId |
| 易车需求 | cityId、serialId、manufacturerId | 易车城市 cityCode、车系 seriesId、厂商 factoryId；必填。每条需求绑定一个城市 |
| 易车需求 | carId、csId2、dealerIds、crId | 车款、副车系、经销商（逗号分隔）、易车需求 ID；通常选填，crId 保留前导零 |
| 易车需求 | brandId | 用于内部核对；不是 saveClue 的入参，不上报 |
| 线索池 | mobile、name、requestIp | 手机号、姓名、请求 IP。上报时手机号去掉 +86；空姓名使用“询价客户”，空 IP 使用 127.0.0.1 |
| 线索池 | cityId、serialId、manufacturerId、carId | 可选填易车编码，与需求已配置的编码不一致则拦截；城市、车系、厂商缺省时使用需求映射 |
| 线索池 | recordPath、ptitle、thirdDeliveryUrl、longitude、latitude、roomId、settleAccountNo、dvid | 录音、页面标题、投流链接、经纬度、直播间、直播账号、设备 ID。经纬度需一起填写 |
| 交付记录 | sourceUrl、orderId | 生成含 platFormId 和本次交付唯一 orderId 的回调地址；orderId 不等于 crId |

线索池的「补充易车字段」及 Excel／CSV 模板支持上述线索属性。易车附加信息在本地加密保存；列表和详情仅公开字典编码与填写状态，分发详情隐藏易车报文中的加密值。测试版在独立的易车请求预览中按 `{"param":{...}}` 组织字段，使用模拟密钥，回调基础地址是不可投递的示例域名。原有本地业务编号继续用于台账，不会被自动当作易车 crId 上报。

旧线索、需求、交付及回调保留。旧易车需求不会自动填入猜测的编码。可在「需求池 → 详情」补齐配置；本机验收可点「填入模拟编码」，保存后再匹配。旧的未发送易车交付若没有新版报文快照，会在执行任务时取消并释放额度，可按新配置重新匹配。已发送历史快照不变。

易车直连推送与回调已按文档实现。日常模拟模式使用独立的模拟报文和回执，正式直连由服务端配置控制。需要正式启用时，设置 `YICHE_ENABLE_LIVE_PUSH=1`，并配置 `YICHE_CID`、`YICHE_SIGN_KEY`、`YICHE_AES_KEY` 和 `YICHE_CALLBACK_URL`。`YICHE_UID` 可选。启用后新建的易车直连交付才会进入真实发送路径。车系、厂商和指定车款会在发送前对照已入库的易车车型库。

`YICHE_CALLBACK_URL` 指向易车可访问的 HTTPS 地址，路径为 `/open/v1/yiche/callback`。本机服务部署在反向代理后时，应转发完整查询参数并使用本机上游 Host。代理日志应省略查询字符串。系统将每笔交付生成的随机校验值随 `platFormId`、`orderId` 一起放入加密的 `sourceUrl`，接收易车按文档追加的 `resultCode` 和 `code`。成功处理或已处理的重复回调返回文档规定的成功响应。

同步响应 `status=1` 记录已接收，回调 `resultCode=0/1` 分别记录使用成功或失败。若 `resultCode` 与文档明确列出的有效或无效原因码冲突，保留回执并标记冲突。明确拒绝释放预占额度。超时和不确定响应保留交付并等待回调，以防重复提交。当前验证覆盖本地模拟的签名、加密、拒绝、超时、重复回调和回调早于同步响应。
