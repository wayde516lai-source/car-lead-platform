# 分媒体车型库、城市库与上报编码

## 管理入口

车型库管理和城市库管理是两个并列栏目。媒体分类来自本组织“合作与渠道”中角色为媒体的主体，最终媒体使用同一主体ID，不另外猜测名称或绑定乙方。新增媒体仍在合作与渠道中操作。车型、城市、API配置、同步任务均按org_id、media_id隔离；会员和KA、不同乙方若最终媒体相同，共用该媒体字典，项目发送协议继续独立。

两个栏目均提供媒体筛选、搜索、20/50/100分页、API配置、立即同步及最近同步记录。没有API的媒体保持未配置和空库，不复制易车数据。API配置需要settings权限，普通read权限可读字典。Token加密保存，不返回已保存值，空输入保留，显式清除才删除。配置更新带版本校验，错误在当前弹窗内显示。

当前支持GET及已核对的errorCode=1、message.data JSON格式。只有接口格式兼容的媒体才能直接配置；其他格式须先按其文档增加适配，不支持任意POST、签名算法或自定义响应路径。

## 易车已确认接口（2026-11-24）

用户提供并只读核对：

- 城市：http://yiche.asoapple.cn/api/v1/pullCityList
- 车型：http://yiche.asoapple.cn/api/v1/pullCarList?page=1

两个接口当前无需Token。本次只读取城市和车型第1页确认结构，没有向业务库导入实网字典或发送线索。城市响应340条，取cityCode、cityName及parentCode、parentName；绝不把行id当cityCode。车型第1页返回100条，count=15843、total=159、page=1。count是总条数，total是总页数，不是总条数。同步从第1页开始，page由服务管理，用户粘贴?page=3也不会漏前两页。

车款取carId，车系取seriesId，厂商取factoryId，品牌取brandId。媒体车型明细继续使用media_vehicle_items，原有库存及字段顺序兼容；城市写入media_city_items。新增配置不会自动初始化或复制媒体、开通项目、开启线索发送。

## 同步及失败处理

保存该媒体该字典的API后即可手动“立即同步”，无需启用每日自动同步。enabled只表示每日自动同步开关；暂停时允许手动任务，不自动改变开关。定时同步按北京时间每日指定整点，默认00:00，服务重启后补当日任务。与其他媒体、另一种字典相互独立。原--no-vehicle-sync参数同时暂停新旧字典定时任务，手动同步不受此参数影响。

网络请求在写事务外执行。车型须全部分页成功、页码和总量一致、实际唯一条数等于count后，才能在一个事务中替换该媒体车型库。空页、重复页、总量中途变化、非法条目、重复编码冲突或超时均保留上一次完整快照。城市空结果同样不清库。同步期间配置变化会使旧任务失效，防止迟到结果覆盖新库。

每个字典最多一个有效任务。失败任务至少间隔15分钟再定时重试；单次最多2000页、200000条，最多45分钟。只允许公开HTTP(S)域名、80/443端口，禁止内网地址及重定向，Token只随HTTPS传递。API错误不回显未知响应报文、Token或含凭证的URL。

旧签名车型源继续兼容；为同一媒体保存新车型API后，旧源停同步，已有车型保留到新源首次完整成功。不允许通过旧配置入口重新启用旧源来竞争写入。

## 需求及线索匹配

手动新增需求跟随所选路由的最终媒体加载车型和城市，后端再次验证媒体归属。车型选择使用带媒体命名空间的内部值，城市选择使用名称；实际发送编码在最终媒体字典中解析。旧隔离模拟需求未配置新字典时保留原测试选项，不自动变成真实外发。

文档、Excel、API来源仍保留原表品牌、车型和城市，不用媒体编号改写上游原文。已有需求业务匹配规则继续共用；厂商品牌辅助识别限定最终媒体，不能用其他媒体库证明品牌归属。全系/全国需求匹配后，发送时仍必须有客户实际意向车系和实际城市。

解析使用品牌/厂商和车系/车款名称规范化精确匹配，多个车款共用同一车系及厂商编号可归为一个候选；多个不同车系/厂商或重名城市不猜测。城市保留省份用于核对；当前历史上海/北京行政区划编码沿用既有名称转换，其他不能识别的编码须补齐城市名称，不能把它直接当乙方cityId。

创建分发、预览、自动分发、可分发统计共用_block校验；可匹配条数继续只表示业务条件匹配。缺库、缺匹配和歧义作为明确拦截原因，创建前不预占。创建时将该最终媒体的编码写入加密交付报文快照，发送前重新校验；编号改变则取消未发送任务并释放预占，已发送交付及回调快照不改。

软米会员协议改用交付最终媒体字典的cityCode、seriesId，不再回退到zmh_mappings或易车直连配置；历史映射表不删除。其他乙方若同样使用易车字典，可共用字典解析，但仍须其独立发送适配器。配置车型城市API不等于已接入该媒体的线索提交协议，也不自动开启任何真实发送开关。

## 数据库及验证

031增加media_dictionary_sources、media_city_items、media_dictionary_runs，旧字典、业务数据、已发交付、回调记录保留，不自动回填真实API配置。迁移只执行一次。旧代码可忽略新表，但旧软米代码不会读取新字典，不能据此认为回退后仍具备相同发送能力。维护清空脚本将新字典表列为保留表，仍拒绝删除被保留字典引用的媒体。

相关测试：tests/test_media_catalogs.py、tests/test_media_catalogs_ui.cjs。真实HTTP/DOM联动通过tests/catalog_http_fixture.py及tests/test_media_catalogs_dom.cjs，固定8879端口，仅用临时库和假API，禁止外网。此类DOM验收不等于浏览器像素验收。实网字典API样本核对与普通自动化测试分开，不让测试连接线上或本地业务库。


## 2026-11-25：同步入口及筛选框修正（本地）

API配置的“同步状态”明确为“每日自动同步”；暂停每日任务时仍允许手动同步，未配置API、正在同步或尚未切换的新旧接口入口仍保持校验。结果状态与自动开关独立展示，手动同步成功不再被“已暂停”覆盖。配置修改的版本校验、旧任务作废及原子替换规则保持不变。

车型和城市栏目共用catalog-filter-form，媒体、关键词标签并列，输入/下拉/搜索按钮固定40px且底部对齐；窄屏单列排列，仅影响这两个栏目的筛选区。
