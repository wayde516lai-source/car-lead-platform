# 架构决策记录

状态说明：“约束生效”指未来开发须遵守，不表示对应能力已实现。下列决定于2026-11-24建立。后续改动新增记录，引用替代的ADR和影响，不覆盖旧结论。

| ADR | 决定及状态 | 原因、代价与复审条件 |
|---|---|---|
| ADR-001 | 约束生效：沿用标准库HTTP+原生JS+SQLite WAL，渐进增加事实层 | 当前交易架构可复用；避免过早重构。分析压测出现锁等待/容量瓶颈时再比较独立存储方案 |
| ADR-002 | 约束生效：当前状态+追加事件/版本/账本并存，不强制全事件溯源 | 保持现有查询兼容，同时可重放；代价是同事务双写及一致性核查；禁止用审计摘要代替完整业务事实 |
| ADR-003 | 约束生效：事件身份与内容分离，业务时间和记录时间并存 | 支撑A→B→A、迟到反馈和时间点建模；需新增事件序号/来源幂等键，内容哈希仅校验内容 |
| ADR-004 | 约束生效：个人信息受限区与分析区分离，按最短必要期限管理 | 历史分析不能成为无限保存个人信息的理由；去标识化仍受控，删除传播与匿名聚合需要额外治理 |
| ADR-005 | 约束生效：需求、交付、尝试、结果、配额、财务分别建模 | 多次重试不等于多卖，接收不等于有效，应计不等于实收；代价是跨账对账 |
| ADR-006 | 约束生效：按时间点及版本生成特征，模型不得越过业务硬约束 | 防止未来信息泄漏和利润评分突破授权；无可靠数据时回退现有规则 |
| ADR-007 | 约束生效：增量迁移与有证据的回填，禁止重造缺失历史 | 已发布迁移不可改，编号实施前核查；历史缺口标注覆盖起点。隐私合法删除与财务冲正分别处理 |

每条后续ADR至少写：日期、状态、问题、备选方案、决定、数据与隐私影响、兼容迁移、验证、回退及替代关系。本文是本次规划决策记录，具体表结构和保留期限仍需实施设计，不能据此启动迁移或生产操作。
