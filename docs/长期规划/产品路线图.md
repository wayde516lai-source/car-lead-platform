# 产品路线图

基线：2026-11-24。以下为依赖顺序，不是已承诺交期；负责人及排期待项目分配。

| 阶段 | 交付范围 | 前置条件及验收门槛 | 状态 |
|---|---|---|---|
| V1.0 数据补强 | P0-01~04：需求时间线、状态事件、失败观测、隐私数据契约 | 临时库验证A→B→A、移除重现、回调乱序/重复/冲突、拒收留痕、撤回删除与恢复，不破坏既有配额 | 规划 |
| V1.0 经营事实 | P1-01~03：成本结算账本、维度版本、质量监控 | 单条交付可对账，未知成本与零成本区分，多卖不重复摊采购成本 | 规划 |
| V2.0 | 时间点可重放的指标集市、趋势、媒体重叠、利润分析 | 与交易账本对账，明确数量周期、迟到窗口与历史缺口，隐私生命周期落实 | 规划 |
| V3.0 | 八类模型的预测及决策辅助；先需求/质量/时效，再利润和成本上限 | 标签成熟、时间切分基线评估、影子运行、解释和人工回退，未达门槛保持规则系统 | 规划 |
| V4.0 | 供需、采购和多媒体组合优化 | V3预测已校准，约束可验证，离线回放后小范围授权实验，支持停止和回滚 | 规划 |

## 实施次序与验收记录

先解决未来继续丢失历史的P0，再补财务及维度P1，最后做P2模型和优化。P0隐私契约必须与历史采集同时设计。不可等待V3才加采样字段。

已有 demand_versions、delivery快照、callback_events、quota_ledger 是基础资产，保留复用，不重建全栈。路线图中每项实际开发结束补：完成范围、提交、验证、迁移编号、发布范围、剩余缺口。历史数据无法恢复的时间段标注 coverage_start_at 和缺失原因；不得伪造回填。当前仅完成规划文档，所有业务整改仍待实施。
