# 数据架构与历史保留约束

## 当前与目标分层

当前交易层为 SQLite WAL、Platform 和既有领域适配器。现有版本、快照、事件和账本继续作为基础，不要求迁移数据库或引入消息平台。

目标数据流：业务动作 → 同事务写入当前投影及最小历史事件/账本 → 提交 → 事务外发送或分析抽取 → 按组织隔离的明细事实 → 日级指标及时间点特征 → 模型预测/决策记录。异步抽取需持久化游标、幂等写入、失败恢复、源端与目标对账；可复用outbox模式，但不能把发送outbox直接当完整分析事件库。达到容量瓶颈再评估独立分析存储，禁止大分析查询长期持有交易锁。

## 事实契约

1. 当前状态可更新，分析事实按事件追加；事件修订以 supersedes_event_id 或 reversal_of 关联原记录。历史快照保存当时需求、路由、价目、规则与维度版本，不能用当前配置解释过去。
2. 事件至少具有 org_id、event_id、aggregate_type/id、event_type、schema_version、aggregate_version、occurred_at、recorded_at、actor_type/id、source_system、correlation_id、causation_id、幂等键及脱敏原因。外部时间未知时留空并记录可信度，不以接收时间冒充发生时间。
3. 租户和对象关联均在后端校验；子表无org_id时经父对象执行组织隔离。新增分析事实优先显式org_id并验证关联一致。业务事件身份不能只由内容哈希决定：A→B→A是三次发生，重传同一事件才去重。
4. 需求按有效区间及观测批次保存：有效时间与系统获知时间分开。每次成功同步需记录项目存在/移除、数量口径、运行ID及观察时间；读取失败不能解释为零需求。每日额度、月额度和总需求不能直接相加。
5. 匹配保留决策时全部合规候选、约束排除原因、选择顺序、规则/模型版本、可用配额和预测值；预览仍不预占。发送尝试独立于交付，超时保持未知。回调首次、重复次数、冲突均可追踪，不重复记账。
6. 采购成本按采集或计费对象记录，明确重复采集是否收费；收入按交付及结算行记录，退款、扣款和调整追加。一个线索多卖共享采购成本，组合收入不能按每个接收节点重复计算。

## 维度与质量

品牌、车系、省市、媒体、主体项目、渠道、路由、价格和规则保留有效期及映射版本。媒体专属代码独立命名空间，外部需求号为字符串。全国/全系是范围条件，不虚构成每市每车型各一份全量需求；拆分须有权重和来源。

每日检查事件缺失、版本断档、孤儿关联、组织错配、重复事件、时间倒序、缺失成本、回调未成熟率及账本对账。未观测、未知、失败、零值必须区分；缺口计入数据质量，不静默填零。批次有行数、摘要、契约版本和覆盖起点，分析可定位到原业务事实。

## 个人信息分离与生命周期

个人姓名、电话、自由文本和原始报文放受限加密区，与分析事实逻辑分离，后续按风险评估物理拆分。分析只用受控随机业务标识、必要维度和金额/结果，映射单独授权。Vault.fingerprint用于现有组织内查重，HMAC和可关联ID仍按个人信息风险管理，不称为匿名数据，不用于跨租户画像。

每类数据上线前登记用途、授权依据、允许接收方、保存起点/结束条件、期限配置、删除/聚合方式及责任角色。个人信息仅保存完成授权用途所必需的最短期限；合同/法定保留要求由项目核定，本文不编造天数或法律结论。期限未核定不是无限保留许可，不扩张采集和分析用途。

| 数据类 | 生命周期控制要求 |
|---|---|
| 联系信息、授权证据、发送载荷 | 按用途及授权到期清除/隔离；证据必要留存范围另行核定 |
| 原始导入、同步原文、失败文本、回调body | 白名单提取必要字段，敏感值不进分析区；短期排障副本到期清理 |
| 可关联明细事实与训练样本 | 仍受授权和期限约束；撤回/删除传播到样本、特征、导出与缓存 |
| 匿名聚合趋势 | 通过再识别风险评估并抑制小样本后，按经营用途周期保留，不默认永久 |
| 财务及审计凭据 | 核定必要依据和期限，最小化个人字段；限制访问和用途 |
| 备份与恢复 | 加密、访问隔离、到期轮换；恢复后先应用删除撤回清单再开放服务 |

删除个人信息应尽量保留合法必要且无法识别个人的经营汇总及追溯凭据，但不得以历史完整为由拒绝删除；需删除的可关联明细按规则清理，标注删除覆盖范围。自由文本、快照和来源历史同样纳入排查。训练集登记数据授权和版本，撤回后判断是否需重训/停用模型并记录决定；禁止恢复备份使已删除信息复活。
