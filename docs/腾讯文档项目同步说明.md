## 操作

进入「需求池 → 腾讯文档项目」。可搜索任一原表字段，按20/50/100条分页，查看每个项目全部字段及原始值。

「同步设置」可调整频率（1～1440分钟，默认30分钟）、开启/暂停、关联媒体、交付路由、KA/会员项目以及数量口径（每日需求量或累计总量）。「立即同步」可手动执行，暂停定时后仍可手动读取。「同步记录」显示每次获取、新增、更新、未变、移除数量和失败原因。

后台服务运行时每10秒检查到期来源，到期后读取。配置和下次执行时间保存在数据库，重启后继续检查到期任务。电脑关闭或后台服务停止时不会执行。

## 数据规则

- 唯一键：本组织、文档、工作表、原表需求编号。同一编号重复同步更新既有记录，行排序变化不产生新项目。
- 完整读取后一次提交本地数据。权限变化、超时、格式变化、重复/缺失编号、空表或分页不完整时保留上次成功结果，并记录失败。
- 上游删除的项目标记为“原表已移除”，可筛选查看历史，不物理删除。
- 有并发同步锁，手动和定时不会同时覆盖同一个来源。中断锁到期后可恢复读取。
- 只向docs.qq.com的表格页面和页面实际提供的公开数据地址发送读取请求，不携带账号Cookie、不跟随其他站点跳转、不调用媒体线索接口。
- 当前采用腾讯公开网页的数据格式读取，网页格式后续变化时可能需要调整解析器；系统会报错并保留已有数据。

## 与匹配分发的关系

原表项目同步时自动关联到真实需求，手动与自动分发共用这些需求和既有分发规则。当前212个项目中202个进行中、10个原表标记结束；结束项目保留全部字段，停止分发。原表移除项目也停止新增分发，未发送任务取消，已发送记录保留。

按用户确认，“下单量”是每日需求量。北京时间每天0点重新计算当日有效、在途和可用数量，历史台账、售卖次数和媒体去重不清零。在途和结果未知占用当日需求额度；最终无效释放需求额度，但仍消耗该线索的售卖次数。达到当日目标后不永久关闭需求，跨日可继续分发。

全系需求可以匹配同品牌具体车型；全国需求不限城市；多地区匹配检查全部地区，页面默认显示第一个地区，点击可展开完整列表。厂商品牌只按车型库中明确的厂商归属匹配，避免跨厂商误分发。结束时间“待定”表示无固定截止日期，直到原表结束、移除或平台暂停；不虚构原表截止时间。

匹配页面读取全部进行中需求，支持超过100条的来源和需求搜索。同步来源指定的会员/KA类型在匹配预览中锁定，避免人工误改。来源字段由原表维护，平台可以单独暂停需求或关闭该需求自动接收。

当前原表需求已打通本地模拟分发，交付快照保留媒体需求编号、车型和地区。真实易车发送继续关闭；未配置真实接口必需字典和参数时不会将模拟任务改为真实发送。

## 接口

- GET/POST `/api/v1/demand-sync/sources`：读取/新增来源。新增需name、url，可配置interval_minutes、enabled、media_id、sale_project。
- PATCH `/api/v1/demand-sync/sources/{id}`：修改配置，需当前version。切换文档请新增来源，避免混合历史。
- POST `/api/v1/demand-sync/sources/{id}/sync`：立即读取，返回SUCCESS或FAILED及逐次统计。
- GET `/api/v1/demand-sync/sources/{id}/projects`：page、page_size、q、present（1当前、0原表移除、all全部）。
- GET `/api/v1/demand-sync/projects/{id}`：项目详情及原始值。
- GET `/api/v1/demand-sync/sources/{id}/runs`：最近20次同步记录。

配置和执行需要demand权限；读取需要read权限，所有操作按组织隔离。迁移016新增3张独立表，不修改已有交付需求和线索。

## 主体优先的手动匹配流程

匹配分发先选择一个采购主体，右侧自动展示符合该主体合作项目、进行中需求和统一分发规则的线索。未选主体默认展示全部可分发线索。切换主体清空原线索选择及筛选，重新计算可分发范围。可逐条勾选，或全选当前筛选结果（包含其他分页）；预览及确认仍执行统一规则和配额校验。GET `/api/v1/matches/leads` 新增buyer_ids；为空或未传时汇总全部可分发线索。filtered_ids为当前筛选结果的全部可选择编号，组织和字段权限继续生效。193项后台回归和4组主体优先页面联动检查通过。

匹配性能优化：同一次线索列表查询中复用车型和厂商归属查询结果，不跨请求缓存；分发确认仍重新校验。需求与线索接口并行加载；当前栏目重复点击不重新加载，筛选和翻页保留页面至新数据返回。可通过“全部主体”取消采购主体限制。193项后台检查及页面流程验证通过。
