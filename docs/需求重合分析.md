# 需求重合分析（第一版，已确认同步开发分支）

入口：需求重合分析。接口：GET /api/v1/demands/overlap，需read权限，所有需求、主体、字典和库存按org_id隔离。只读，不预占库存、不创建或执行分发、不调用真实外部接口。

## 展示范围

未结束且主体/项目启用的ACTIVE、PAUSED需求。已结束、已完成、已移除及已到结束时间的需求排除。按共享车型名称规范化和城市名称分组，数字和字母保留；品牌为展示信息。会员/KA在明细区分，可按项目筛选。默认仅显示两项及以上需求命中的组；可取消仅看重合以看单项机会。同媒体经不同主体或路线的需求不会变成多家媒体。

全系按本组织内部车型及媒体车型库、其他需求中可核实的同品牌具体车型展开；全国按当前需求已明确的具体城市展开。不能核实范围时显示带品牌隔离的全系或全国“范围待展开”组，不把不同品牌的未知全系合并，不伪造具体城市/车型或库存数字。分组超过20000项时明确要求按车型/城市搜索缩小范围，不静默截断。

## 量级与库存

- 每日目标：API需求使用当前每日提交量；DAILY需求使用每日目标；TOTAL需求仅取每日限额，不取项目/月度总量。
- 同最终媒体同组取最大值作为保守参考，不推测同媒体多份订单是否可叠加。跨媒体参考交付量为这些目标之和，共同覆盖量为不同媒体目标的最小值；只有一家媒体时共同覆盖量为0。
- 今日剩余沿用既有每日账本、API提交计数与总配额限制，不修改计数。多车型、多城市、全国/全系展开后的行共享原需求额度，不能跨行相加。
- 独立线索参考下界按今日剩余量计算：不低于单媒体最大剩余，也不低于剩余交付参考量除以配置累计售卖上限向上取整。这只是下界，未推断未知未来线索授权、KA组合、共享额度分配和合同条件。
- 当前库存按线索去重，逐条使用既有_block校验当前范围内至少一项需求；逐条可分发不保证整个集合可同时创建。无brand/model/city字段权限不计算或返回库存；范围待展开时库存留空。明细展示已核对的拦截原因，无库存时不声称完成逐条校验。
- 建议补充量本版保留待核算，不将参考下界减库存伪装成精确采购建议。先支持每日量优先、媒体覆盖优先，未知补充量不参与虚假精确排序。

## 交互和交付边界

搜索品牌/车型/城市，项目筛选、仅看重合开关、排序、分页、重置；行内展开合作主体、媒体、会员/KA、需求编号、每日目标/剩余、共享额度提示、状态/拦截原因和结束时间。所有文本转义。

本版无热力图、无数据库迁移、无真实发送；更新8879隔离预览供用户验收，不修改线上。用户已确认同步本次代码到开发分支，合并及上线仍需另行安排。
