# 统一代码书写规范

版本：1.0｜生效日期：2026-11-16。

本文规定代码“怎么写”；[开发规范](开发规范.md)规定职责、业务约束与发布方式；[注释规范](注释规范.md)规定代码“为什么这样写”如何说明。三份配套使用，AGENTS.md是Codex入口。示例是写法示范，除注明现有接口外不代表已新增业务方法。

## 1. 适用范围与执行方式

- 新增模块和实质改写的方法按本规范执行；已有API字段、数据库字段、错误码、函数签名和前端路由不能只为改风格而破坏兼容。
- 局部修复只整理涉及的逻辑块。整文件格式化、跨模块重命名和业务改动分开，不把“统一规范”作为全仓重写授权。
- 文件UTF-8、LF换行、末尾保留一个换行，不保留行尾空格。排版基准见项目根.editorconfig；该文件只指导编辑器，不自动重写历史文件。
- 单行以120字符为目标。长URL、必要字符串可例外，避免为凑长度拆坏协议或SQL。
- Python新文件4空格；新独立JS/CSS文件2空格；SQL按4空格对齐。对旧文件局部修改保持块内一致，不混用Tab。
- 不用空白行数量、函数长度、注释行数作为唯一质量指标。重复规则、有副作用的隐式行为、无法理解的长流程才是拆分理由。

## 2. 全项目命名对照

| 对象 | 规则 | 推荐 | 避免 |
|---|---|---|---|
| Python文件/函数 | snake_case | demand_sync.py、receive_callback | doStuff、handle_all |
| Python/JS类 | PascalCase | DeliveryResult | data_class |
| JS变量/函数 | camelCase | selectedLeadIds、renderLeadTable | a、tempData2 |
| 常量 | UPPER_SNAKE_CASE | CALLBACK_PATH | callbackpath |
| SQL表/列及内部JSON字段 | 兼容既有snake_case | org_id、price_fen | 随意改为orgId |
| CSS class / DOM id / action | kebab-case、按模块前缀 | demand-filter、data-action="preview" | 无范围的new-style |
| 布尔变量 | 表达可判断的条件 | isEnabled、has_permission、can_dispatch | flag、status2 |
| 金额/时长 | 名称带单位 | price_fen、timeout_seconds | amount、timeout_num |
| 集合 | 复数或语义后缀 | leads、delivery_ids、demandById | list1、data |

本项目actor可以是登录用户、系统任务或经过验证的回调身份；不要都改名为user。lead是线索、demand是需求、delivery是一次交付、attempt是网络尝试、event是事件，不能互相替代。buyer、receiver、media分别表示采购主体、直接接收方、最终媒体。

对方字段如resultCode、serialId保留协议原名，在边界统一映射；不要把对方大小写风格蔓延到内部模型，也不要改协议字段名来迎合内部风格。

## 3. Python排版与导入

一行一条语句；赋值、运算符两侧有空格，逗号后有空格。长调用用括号换行，多行参数保留尾逗号；顶层函数/类之间两行，类内方法之间一行。不要通过反斜杠续行压缩复杂条件。

```python
# 不推荐：名称模糊，校验、写入和返回混在一起。
def save(c,a,d):
 if not d['name']:raise ValueError('empty');c.execute('...');return True
```

```python
# 推荐：按处理阶段展开，具体持久化仍由领域服务实施。
def normalize_customer_name(raw_name: str) -> str:
    customer_name = raw_name.strip()
    if not customer_name:
        raise ValueError('客户姓名不能为空')
    return customer_name
```

字符串默认单引号，包含单引号时可用双引号减少转义；docstring用三双引号，多行SQL用三引号。JSON文件使用合法双引号；不要手工拼JSON。局部修改不强行转换旧引号风格。

导入分组：标准库→第三方→项目内，各组间一空行。每个import语句职责清楚，不用星号导入；不要为避免循环依赖随意把所有导入移入方法。确有宿主Mixin循环依赖时允许局部导入，并解释原因。

```python
import json
from pathlib import Path

from cryptography.fernet import Fernet

from security import canonical, digest
```

依赖显式引入，不依赖另一个模块偶然import过的名字。新增第三方依赖要说明用途、锁定版本并验证服务器环境，不自动升级现有锁定依赖。

## 4. 函数、类、参数与类型

- 一个函数围绕一个业务动作；解析、校验、数据库事务和HTTP传输分阶段表达，不强制每阶段都建类。
- 参数超过约5个时评估关键字参数或dataclass，重点是能读懂及约束明确，不能只改成一个无约束dict。扩展公共签名前核对调用方。
- 不使用可变默认值；可选值用None，函数内部再建立集合。不通过修改调用方传入dict隐式返回结果，确有原地修改须在名称/说明中标明。
- 新增公共方法优先类型注解。边界dict注明必填字段；内部可用dataclass表示稳定结构，不为加类型新引框架。
- 同一方法返回结构稳定。不要一会儿返回bool、一会儿返回记录、一会儿返回错误字符串。错误走明确异常；异步业务状态放结构化结果。
- 小型纯函数不必机械写Args/Returns；交易、回调、权限接口按注释规范写清事务和副作用。

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class QuotaSnapshot:
    target: int
    reserved: int
    valid: int


def calculate_remaining(snapshot: QuotaSnapshot) -> int:
    return max(0, snapshot.target - snapshot.reserved - snapshot.valid)
```

上例只表达数量，不代替当前_daily_counts、账本、每日/总量规则；不得把展示纯函数直接当作占用库存的业务校验。

```python
# 错误：多次调用共享默认列表。
def collect_ids(selected_ids=[]):
    selected_ids.append('example')


# 推荐：本次调用独立构建集合。
def normalize_ids(selected_ids: list[str] | None = None) -> list[str]:
    return list(dict.fromkeys(selected_ids or []))
```

业务标识、外部编号和电话号码使用字符串，保留前导零。不要把手机号作为整数，不把外部编号强制int后再转回文本。

## 5. 条件判断、校验与异常

使用提前返回/抛错减少嵌套。None用is None，不用if value代替所有空值判断；0、空字符串和未提供字段需要分别处理。布尔不能被当作合法数量：Python中bool是int子类，严格整数边界应按需求验证type(value) is int。

```python
from decimal import Decimal


def yuan_to_fen(text: str) -> int:
    amount = Decimal(text)
    if not amount.is_finite() or amount < 0 or amount.as_tuple().exponent < -2:
        raise ValueError('金额须为非负数，最多两位小数')
    return int(amount * 100)
```

上例的Decimal解析错误应在调用边界转换为本项目Fault，不应直接暴露给用户；不使用int(float(text) * 100)。格式限制、最大金额仍按具体接口验证。

校验分三层：HTTP层校验报文结构，领域层校验权限、必填、关联和业务约束，协议层校验对方编码及字段。不能只靠前端或Excel模板限制。

只捕获能处理的异常。业务错误使用Fault及中文提示，不泄露堆栈、SQL、令牌或客户字段。常规请求不要except Exception: pass；任务顶层可捕获未知异常以保活，但必须记录脱敏标识并保留可排障证据。

```python
# 不推荐：将一切失败冒充成功。
try:
    synchronize_source()
except Exception:
    return {'status': 'SUCCESS'}

# 推荐：边界根据可识别失败保留已有数据，并让调用方知道结果未知/失败。
try:
    parsed_rows = parse_source_response(response_body)
except ValueError as error:
    raise Fault('SOURCE_RESPONSE_INVALID', '来源数据格式异常，已有数据未覆盖') from error
```

最后示例中的解析函数和错误码为写法示范；实际接入沿用对应领域的异常类型，不复制为所有同步的统一错误。对外响应禁止直接str(error)返回任意底层异常。

释放文件/连接优先with或finally；事务失败必须回滚；不要在finally中return掩盖原始错误。

## 6. 常量、配置、时间和金额

- 固定协议字段、路径、状态枚举用已有常量或集中定义；不重复散落魔法字符串。
- 可调业务规则从settings或领域配置读取，不能写成常量；默认上限不代表永久政策。
- 环境变量在启动/配置边界读取、验证并传入。密钥字段使用repr=False等避免意外打印；不要用默认真凭证或自动回退到文档示例Token。
- 日期计算复用now/later/parse/day。区分UTC ISO文本、epoch秒和毫秒；新字段在名称/文档中声明，禁止混用本地naive datetime和带时区时间。
- 前端北京时间展示明确指定Asia/Shanghai；不以浏览器所在时区决定每日配额日界。
- 金额持久化为整数分，百分比说明分子分母，数量总计明确去重粒度。

## 7. SQL书写与数据库访问

关键词大写，表/列snake_case；复杂SQL展开SELECT、JOIN、WHERE、GROUP BY、ORDER BY，用有业务含义的别名。更新只列需要改动的字段，插入显式列出列名；不要依赖列的自然顺序。

```python
row = conn.execute(
    '''
    SELECT id, status, target_total
    FROM demands
    WHERE org_id = ? AND id = ?
    ''',
    (actor['org_id'], demand_id),
).fetchone()
```

```python
# 禁止：将用户输入直接放进SQL。
query = f"SELECT * FROM demands WHERE demand_no = '{demand_no}'"
```

值通过占位符；动态表名/排序列必须映射固定白名单。SQL参数校验不能只靠正则过滤引号。

写事务复用Platform.tx()；事务内使用传入conn，避免嵌套连接互相锁住。跨步骤事务由业务动作统筹；HTTP等待和大文件解析放在写事务外。新外部发送保持“提交任务领取→网络请求→提交结果”，不把网络请求夹在SQLite写锁中。

分页必须稳定排序：时间字段再加id。总数查询与列表查询使用同一筛选条件；聚合前检查JOIN是否造成重复计数。新增索引给出查询场景，以实际执行计划验证，不能把所有字段都建索引。

迁移用新编号登记_migrate及schema_version，已发布文件不改。当前按分号拆分迁移，注释/字符串不含分号，不新增依赖内部分号的trigger；详细兼容规则见开发规范。

## 8. JavaScript排版与数据处理

使用const为默认，只对确实要重新赋值的变量使用let，不新增var。使用===/!==，避免隐式类型转换。新代码统一分号，单引号；对象/数组长表达式换行，不能用一整行模板容纳完整页面的业务逻辑。

```javascript
const selectedIds = [...state.selected];
const hasSelection = selectedIds.length > 0;
const pageSize = Number(form.elements.page_size.value);
```

数值来自输入时显式转换并用Number.isInteger/范围验证；空字符串不应无意变为0。金额输入交由后端精确校验，不在前端累加浮点决定结算。

用map生成显示项、filter筛选展示、find取单项、Set做明确的去重。不为一行代码链式嵌套多个map/filter/reduce而牺牲可读性。共享资格规则、最终状态和配额在后端计算，不能在视图复制业务判断。

函数命名说明目的：renderDemandSummary、buildFilterParams、loadDeliveryDetail，而不是processData。纯渲染与事件写操作分开，复用render、api和data-action；需要新增模块时保持单一页面入口。

## 9. 异步、事件和安全渲染

依赖操作顺序await；独立只读请求可Promise.all，并明确失败表现。不能把付款/分发创建等有副作用的请求当作性能优化随意并发。

```javascript
const [report, demandPage] = await Promise.all([
  api('reports/funnel'),
  api('demands?page_size=20'),
]);
```

不要catch后继续渲染空值冒充请求成功。需要部分成功时明确呈现失败部分，而不是无声降级。

```javascript
async function submitPreview(button) {
  button.disabled = true;
  try {
    await api('matches/preview', 'POST', buildPreviewPayload());
  } catch (error) {
    toast(error.message, true);
  } finally {
    button.disabled = false;
  }
}
```

上例是结构示范；matches/preview沿用现有端点，buildPreviewPayload仅为示例占位函数。接入时使用项目实际的参数构建、全局事件处理和恢复机制，不重复绑定异常处理。提交按钮禁用只能防止部分误点，业务幂等由后端保障。

切换页面/筛选后的响应可能乱序，复用现有renderSequence；必要时AbortController取消旧请求。旧请求完成后不能覆盖新页面或清空新选择。

所有外部/用户文本插入HTML前esc()；URL另用URL/URLSearchParams编码和协议校验。禁止字符串拼接内联onclick或把用户内容放进style。按按钮data-action事件委托，不按tbody tr:nth-child等位置识别业务记录。

更新页面尽量保留当前筛选和分页，跨页面清理仅在明确流程中执行。加载、空结果、失败、成功需要区分；报错保留可追踪request_id的途径但不展示凭证。

## 10. CSS书写

规则块展开写，属性一行一个，2空格缩进，属性值后保留分号。遵循布局→尺寸→间距→排版→外观→交互的顺序，减少同属性重复覆盖。

```css
.demand-summary-actions {
  display: flex;
  align-items: center;
  gap: 8px;
  padding: 12px;
  color: var(--ink);
  border: 1px solid var(--line);
}
```

使用现有CSS变量和组件类；新专用选择器加领域前缀，避免全局button、label改动牵连所有页面。不要使用!important掩盖层级问题；确需使用时说明覆盖对象和删除条件。

优先flex/grid和minmax(0, 1fr)控制布局。筛选按钮对齐表单输入框；长车型/多城市内容截断或折叠，不能撑破容器。表格横向滚动，弹窗受视口限制，键盘焦点可见。新增布局至少核查桌面和窄屏，不能以jsdom代替视觉验收。

尽量不用固定高度容纳动态内容；z-index沿用现有层级，不任意增加到999999。内联样式只用于可控的动态值，固定样式放style.css。

## 11. 日志、审计与注释

日志服务排障，审计记录业务动作，两者不能互相替代。沿用现有日志/审计入口，不为单个功能引入全新日志框架。

推荐记录：request_id、内部delivery_id、动作、脱敏错误码、发送尝试编号、耗时；不记录姓名、手机号、完整请求URL、Authorization、Cookie或回调令牌。对方GET接口含个人信息时尤其不能直接print(request.full_url)。

异常和回调消息里的未知外部文本不能直接当可信HTML。审计动作区分MOCK_SEND、ZMH_SEND_CLAIMED等实际来源，不把真实HTTP发送标为模拟。

模块、公共业务接口、复杂状态/事务说明遵循注释规范；注释不写“新增代码”“修改一下”等无意义历史，不虚构依据。修改行为同时修改注释和测试，不将逻辑变动包装成纯注释变更。

## 12. 测试代码怎么写

沿用unittest，不默认新增pytest。文件test_领域.py，方法test_条件_预期；准备→执行→断言分段，多个场景可subTest，复杂fixture提取清晰辅助函数。

```python
import unittest


class RemainingQuotaTests(unittest.TestCase):
    def test_full_quota_returns_zero(self):
        snapshot = QuotaSnapshot(target=5, reserved=2, valid=3)

        remaining = calculate_remaining(snapshot)

        self.assertEqual(remaining, 0)
```

上例需引用第4节示例定义才可执行，并非要求项目新增同名测试。真实功能测试优先验证业务后果：是否多卖、是否重复计账、是否跨组织、未知结果是否被错误覆盖。不能只断言函数被调用或HTTP200。

数据库用TemporaryDirectory隔离；网络用假传输；时间相关测试控制时间或明确时区，不靠sleep等待自然过期。不要在普通测试中读data/platform.sqlite、生产凭证、临时宝塔会话文件，或向真实对端发请求。

Mock在使用该依赖的模块边界替换，测试后恢复环境变量，避免外发开关串到其他用例。导入测试fixture时注意unittest可能重复收集被导入的TestCase，可通过模块别名引用fixture。

现有环境可运行的检查（在项目根目录、对应依赖环境下）：

## 14. 代码评审与逐步整改

每次审阅确认：

- 命名能否区分线索、需求、交付、尝试、事件和主体角色？单位/时区是否明确？
- 是否新增了压缩语句、可变默认值、静默except、隐式类型转换或前端重复规则？
- 组织范围、参数化SQL、输入校验、事务及网络边界是否落实在代码？
- 是否保留现有字段/路由/签名兼容，配置是否显式，外发范围是否受控？
- 异步、重复请求、回调乱序、未知结果和错误展示是否可处理？
- 是否有适当测试、更新注释和领域说明，且未把测试数据计入真实指标？

整改按本次修改涉及范围推进：先展开高风险交易/回调流程，再统一领域命名、提取重复校验，最后按实际需要拆模块。不要机械把所有单字母重命名或把每段代码都包装成类；能够理解、验证和安全修改才是目标。
