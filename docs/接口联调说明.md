# 本地接口联调说明

完整接口描述见openapi.json。所有编号示例仅用于本地测试，不代表真实媒体协议。

## 管理端会话

POST /api/v1/login：提交username、password，获取HttpOnly会话Cookie和data.csrf。后续写请求携带Cookie与X-CSRF-Token。分发提交额外携带Idempotency-Key。

请求成功包装为code、message、data、request_id；普通列表支持page_size=20、50、100和page，部分列表支持q、status、channel、media。真实字段以OpenAPI和当前服务实现为准。

## 来源上报

POST /open/v1/leads。测试凭证X-Key-Id=TEST-SOURCE_ADS，绑定ADS渠道，不能通过body切换来源。可以提交单条或items数组（最多100条），字段source_record_id、phone、series_id、city_code、collected_at、recipients数组及evidence_ref。返回202逐项处理结果；新授权仍需合规核验。

## 回调

POST /open/v1/callbacks/MEDIA_A（也可MEDIA_B或AGENCY_A）。测试凭证分别为TEST-MEDIA_A、TEST-MEDIA_B或TEST-AGENCY_A。共同测试签名密钥：TEST-ONLY-CALLBACK-SECRET-2026。该固定密钥仅用于隔离的本地模拟，禁止生产复用。

Headers必须含X-Key-Id、X-Timestamp（Unix秒）、X-Nonce、X-Signature。签名原文：大写method、path、timestamp、nonce和SHA256原始请求body的十六进制摘要，以换行连接。用测试secret执行HMAC-SHA256后Base64。偏差不超过300秒，nonce10分钟去重。每次重试用新nonce，复用event_id。

回调body字段：event_id、delivery_id或唯一external_delivery_id、event_type、event_version、occurred_at、final_media_code、data。有效性放在data.validity=VALID或INVALID。MEDIA_STORED/MEDIA_REJECTED更新入库维度；VALIDITY_UPDATED/RESULT_CORRECTED更新有效维度。其他客户个人信息字段会被拒绝。事件编号和版本按回调主体作用域管理。

回调先持久化再应答，随后由POST /api/v1/inbox/run处理。未知编号返回202并进入UNMATCHED，不按手机号猜测关联。相同事件编号不同内容409，持久化失败503。

## 运行方式

测试环境为显式执行：匹配并确认创建交付后，调用worker/run执行模拟发送；开放回调入库后调用inbox/run归一化。页面中的模拟回调会先持久化再立即触发归一化。所有worker操作受组织及角色权限保护。

当前没有真实HTTP出站客户端。TIMEOUT模拟为UNKNOWN，禁止自动重发；支持查询的模拟适配器可用reconcile确认接收结果，不增加发送尝试。
