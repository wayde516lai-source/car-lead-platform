# 汽车线索平台本地测试系统

依据《汽车销售线索数据管理平台 PRD v1.1》实现的可持久化业务测试版。仅使用虚构客户和模拟媒体，不可直接投入真实客户生产业务。

## 代码维护入口

后续维护先阅读[统一开发与维护规范](docs/开发规范.md)、[统一代码书写规范](docs/代码书写规范.md)、[统一注释规范](docs/注释规范.md)及[AGENTS.md](AGENTS.md)。变更记录见[CHANGELOG](docs/CHANGELOG.md)。新规范替换旧规范，历史代码按实际修改范围逐步整理。

本文其余部分主要记录早期本地测试基线。当前已部署线上，并新增软米乙方实网测试等能力；接口现状以对应领域说明和实际版本核验为准，不以旧的“全部模拟”描述推断所有通道状态。

## 首次初始化与启动（2026-11-22更新）

普通启动不生成演示账号、线索或需求。全新数据库没有用户时，服务会停止并提示先创建管理员：

```sh
python3 scripts/init_admin.py --data /你的私有数据目录 --username 你的管理员账号
python3 server.py --data /你的私有数据目录 --host 127.0.0.1 --port 8765
```

初始化命令在交互终端隐藏输入两次密码（至少12字符），仅创建一个管理员及组织配置，分发默认关闭。组织默认标识为main，可用`--org-id`指定。已有账号或已有组织配置时拒绝重复初始化，不覆盖旧账号。数据目录与加密密钥必须私有保存。

已有业务数据库正常沿用原账号；更新代码不会重置密码，也不会删除历史数据。登录页默认提供账号输入框，不预填或展示演示密码。

仅在独立临时目录、确实需要本机演示时，显式运行：

```sh
python3 server.py --data /tmp/carlead-demo --seed-demo --no-vehicle-sync
```

`--seed-demo`只允许回环监听、未开启公开测试及外发开关的环境；已有用户时不补写样例。不要在正式服务参数中添加此选项。下文验收及演示账号说明均仅适用于显式演示数据，不能作为正式账号配置。双击本机启动脚本也不会自动造数。

## 推荐验收顺序

1. 用管理员进入「验收向导」，阅读自动验收结果，并检查当前数据库一致性。
2. 进入「表格导入」，下载Excel模板。模板内含一条正确记录与一条错误号码。上传后确认可导入、重复、错误分类，再仅导入合格行。
3. 进入「匹配分发」，点击「选择示例前5条」，勾选媒体需求 `000123` 与 `AUTOHOME-0098`，生成预览。初始数据应有10条合规匹配；确认创建后进入分发记录，点击「执行待发送任务」。
4. 打开任一分发的「完整链路」，查看媒体原始需求编号是否与车型同一报文，分别点击模拟媒体入库、模拟有效、模拟无效，核对状态与需求有效量变化。
5. 在「合作与渠道」里把某路由设为模拟超时，再用未上报过的合规线索创建交付，观察结果未知保留配额。配置只作用于新交付。
6. 在「系统设置」修改媒体数量上限，查看新预览按配置拦截。降低不会撤销历史披露；会取消超限未发送任务。
7. 切换运营账号申请脱敏导出，再切换合规账号审批，最后由原申请人下载。本人不可自审，下载仅一次且15分钟过期。
8. 用合规账号在线索详情撤回或删除，检查未发送交付取消、历史接收方生成通知。通知确认是模拟动作。

示例说明：初始有13条线索，其中前5条用于5×2验收；另有1条独立历史有效交付。易车示例需求总量6、历史有效1，因此仍剩5条可用。重复执行分发案例会被去重或配额规则拦截，这是正常行为。测试脚本始终使用独立临时数据库，不会重置你操作的测试数据。

## 当前已实现

- 本地账号与角色权限、同组织访问范围、会话与CSRF保护。
- 渠道、合作方、标准车型与城市；直连及乙方转发路由配置。
- 人工/API/Excel/CSV线索入库，预检与字段映射、去重、错误行下载；授权核验后可分发。
- 媒体原始需求编号、草稿/审核/暂停/关闭/数量及价格版本；历史交付快照。
- 匹配原因、原子预占、同媒体跨路径去重、多售上限、日配额、全局停发。
- 持久outbox/inbox、分层状态、回调事件幂等与版本控制、结果冲正、模拟超时及查询。
- 线索完整来源、每笔交付、节点、尝试、回调和配额账本可查。
- 脱敏查询、单独授权查看明文、双人导出审批、撤回删除及接收方通知任务、审计。
- 全量首次发送队列统计、来源×媒体表现、成本不重复计入、预估收入。
- 一致性检查、加密本地备份、恢复后的删除清单重放。

## 与完整生产PRD的差异及未完成事项

这是一版本地业务测试系统，并非PRD全部P0的生产交付：

- 推荐技术栈替换为Python标准库HTTP服务、原生HTML/JS/CSS和SQLite WAL，方便本机直接运行。SQLite事务用于验证业务一致性；尚未实现PostgreSQL、Redis、BullMQ、OIDC/MFA、S3/KMS及生产部署。不能由此推断生产并发能力。
- 真实媒体/乙方接口资料未提供，全部使用本地模拟；未实现真实HTTP发送、对端幂等查询、自动退避重试、熔断及媒体字典发布回滚。当前worker由按钮或API显式执行，不是常驻自动调度器。
- 已激活需求调整数量价格会直接留审计及版本，本地版尚未补齐变更的双人审批流程；初始需求审核及导出审批已分人。
- 报表目前按全量发送队列统计；日期队列、事件日期、日报快照、延迟P50/P95和复杂维度筛选尚未实现。
- 未匹配回调已持久化，可检索；自动重新关联、人工挂接、死信重放审批及复杂手工更正工单尚未实现。有效性更正在测试版通过带版本模拟回调完成。
- 目前组织隔离及角色权限已实现，尚未实现同组织内按渠道/采购方细分的数据范围。外部凭证为测试固定配置，无生产密钥轮换管理界面。
- 有明确来源合同、授权及独家拦截；复杂反欺诈、投诉管理、未成年人核验、到期自动清理、法定留存/限制处理流程仍需完善。
- 删除本地个人信息及历史载荷；外部通知在测试系统记录，不会真的联系接收方。备份和删除清单应成套保护，生产需补齐异地及事务化治理。
- 10万/100万规模压测、100/200每秒持续吞吐、SLA、异地恢复及安全评审均未执行。
- 自动化28项结果的范围是本地领域逻辑及部分HTTP接口；AC17以重复任务投递验证不会多记账，不能代替真实网络重试测试。界面验证以独立报告为准。

## 数据与启动

数据位于 `data/platform.sqlite`；本地加密密钥为 `data/.local-key`；独立撤回删除清单为 `data/privacy-tombstones.jsonl`。刷新、重启不会清空数据。禁止只复制数据库而丢失密钥或删除清单；不要将data目录提交到版本管理或发送他人。

依赖：Python 3.12、cryptography、openpyxl。当前电脑可用的预装运行环境会被启动脚本自动选择；其他电脑需安装requirements.txt。

```sh
python3 -m pip install -r requirements.txt
python3 server.py --port 8765
python3 tests/test_acceptance.py
```

服务只监听127.0.0.1，不开放局域网，不配置真实媒体URL。备份通过系统设置按钮创建，恢复只允许离线工具进行，避免误点覆盖现有数据。

## 文件位置

- `domain.py`：业务规则与事务。
- `security.py`：本地加密、指纹、密码和签名。
- `server.py`：HTTP、认证和接口。
- `migrations/001_initial.sql`：表结构、索引和约束。
- `static/`：全部操作页面。
- `tests/test_acceptance.py`：28项独立本地验收。
- `docs/`：验收结果、接口规范、业务数据关系及操作说明。

易车专用字段及本地验收方式见 docs/易车字段说明.md。

## 可配置分发规则与自动分发

已支持累计售卖上限、KA限制、滚动去重窗口、需求五星达成率、同媒体限制、规则版本审计，以及共用规则的手动/自动分发。自动分发默认关闭，需先在需求详情明确项目并开启自动接收。参见[分发规则使用与验收](docs/分发规则使用与验收.md)。

## 腾讯文档项目定时同步

需求池新增腾讯文档项目区，可同步原表全部字段、按需求编号更新、查看移除历史、调整同步频率和查看失败原因。原表项目自动关联可分发需求，支持每日配额、全系/全国/多地区匹配，已结束项目保留展示并停发。参见[同步说明](docs/腾讯文档项目同步说明.md)。
